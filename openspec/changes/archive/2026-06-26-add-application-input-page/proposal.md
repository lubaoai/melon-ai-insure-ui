## なぜ

意向確認画面（ステップ②）までの画面は実装済みだが、その次のステップである「申込内容入力画面」（ステップ③）が未実装である。意向確認画面の「次へ」ボタンは現在コンソールログ出力のみのプレースホルダー状態となっており、申込入力画面を実装することで画面遷移が繋がり、ユーザーが申込情報を入力できるようになる。

## 変更内容

- 申込内容入力画面（ApplicationInputPage）を新規実装する
  - ルート `/application-input` を追加し、意向確認画面の「次へ」ボタンから遷移可能にする
  - StepNavigation のステップ3（③申込内容入力）をアクティブ表示する
  - 以下の7つの入力セクションを含む：
    - ①契約希望日セクション：契約希望日（yyyy/mm/dd形式の日付入力）
    - ②ご契約コースセクション：保険期間（1年/2年）、保険料のお支払方法（クレジットカード払）、商品（ラジオボタン）、プラン種別（ドロップダウン）、保険料（読み取り専用）、保険料の種類（読み取り専用）
    - ③住居の概要セクション：構造（木造/非木造）、形態（アパート・マンション/戸建て）、形態備考（階建中・階）
    - ④ご契約者様の情報セクション：契約種別（個人/法人）、契約者氏名・氏名カナ・性別・生年月日・住所（郵便番号+番地まで）・建物名・部屋番号・住所フリガナ・電話番号
    - ⑤住居の所在地セクション：「契約者と同じ」コピーボタン付き、郵便番号+番地まで・建物名・部屋番号・住所フリガナ
    - ⑥主たる居住者セクション：区分（契約者と同じ/異なる）、氏名・氏名カナ・性別・生年月日・契約者との続柄・続柄備考・電話番号（「契約者と異なる」選択時のみ表示）
    - ⑦同居人の明細セクション：同居人の有無（なし/あり）、ありの場合は最大5名の同居人情報（氏名・氏名カナ・性別・生年月日・契約者との続柄・続柄備考）
  - ナビゲーションボタン（戻る・次へ）を実装する
  - ヘッダー、フッター、ステータスバー、Q&AサイドバーはHomePageから流用する
- 意向確認画面の「次へ」ボタンの遷移先を `/application-input` に更新する

## 機能一覧

### 新規機能
- `application-input-page`: 申込内容入力画面のページルーティング、レイアウト構成、ナビゲーション
- `application-form-sections`: 申込入力フォームの7セクション（契約希望日・ご契約コース・住居の概要・ご契約者様の情報・住居の所在地・主たる居住者・同居人の明細）の入力コンポーネント

### 修正機能
- `intent-confirmation-page`: 「次へ」ボタンの遷移先をコンソールログから `/application-input` への実際のナビゲーションに変更
