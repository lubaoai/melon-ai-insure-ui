# 品質レビュー

## 1. 境界条件

**ステータス**：⚠️ 警告

**発見事項**：
- contract-summary-section と caution-section に空値・null のシナリオが定義されている（✅）
- intention-confirmation にチェックボックスの境界条件（両方オフ→片方オン→両方オンの遷移）が記載されている（✅）
- チェックボックスの境界条件として「確認ON・同意OFF」と「確認OFF・同意ON」の2パターンが次へボタン制御でカバーされている（✅）
- 不足：スクロール位置が境界値（最下部-1px）の場合のチェックボックス活性化判定が未定義

**提案**：
- スクロール判定はpage01と同様に「scrollHeight - scrollTop - clientHeight < 10」で実装するため、仕様上は問題なしと判断

## 2. ロールバック方案

**ステータス**：✅ 合格

**発見事項**：
- 新規画面・新規コンポーネントの追加のみであり、既存データの破壊的変更はない
- ルーター設定の追加のみで、削除時はルート定義を除去すればロールバック可能
- データベース移行やAPI変更が伴わないため、ロールバックは容易

**提案**：
- 特になし

## 3. テストカバレッジ

**ステータス**：⚠️ 警告

**発見事項**：
- 各specにシナリオが定義されており、テストケースの方向性は明確（✅）
- contract-summary-section: 5要件・8シナリオ
- caution-section: 2要件・3シナリオ
- intention-confirmation: 3要件・5シナリオ
- intent-confirmation-page: 4要件・4シナリオ
- 不足：スクロール連動のjsdom環境制約に対するテスト戦略がdesignに明記されていない

**提案**：
- スクロール連動テストはpage01のTermsSectionテストと同パターン（data-testid付きスクロール領域＋scrollTop直接操作）で対応する

## 4. 後方互換性

**ステータス**：✅ 合格

**発見事項**：
- 既存のHomePageやコンポーネントに変更を加えない
- 新規ルートの追加のみであり、既存ルートへの影響なし
- StepNavigationはcurrentStep=2で流用するのみ

**提案**：
- 特になし

## 全体評価

**分割方向の提案**：
1. **ContractSummarySection** — アンバー見出し＋マゼンタ見出し＋スクロール領域＋確認チェックボックス（TDD）
2. **CautionSection** — マゼンタ見出し＋スクロール領域＋全文を見るリンク（TDD）
3. **意向確認セクション** — マゼンタ見出し＋同意チェックボックス＋戻る/次へボタン（TDD）
4. **IntentConfirmationPage** — ページ統合＋ルーター設定
5. **統合確認** — ビルド・全テスト実行

**優先順位付け**：
- ContractSummarySection → CautionSection → 意向確認セクション → ページ統合の順（コンポーネント単位で下から上へ積み上げる）

**粒度の基準**：
- 各コンポーネントについて「失敗テスト作成→最小実装→成功確認→コミット」のTDDサイクルを1タスクグループとする
- 1ステップ2〜5分程度：テスト作成1分、実装2分、確認1分、コミット1分
