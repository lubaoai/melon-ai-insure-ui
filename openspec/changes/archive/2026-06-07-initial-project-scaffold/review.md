# 品質レビュー

## 1. 境界条件

**ステータス**：✅ 合格

**発見事項**：
- msw-api-mock仕様にて、必須フィールドの欠落ケース（TypeScriptコンパイルエラー）、APIエラー時のハンドリング、IDの一意性をカバーしている
- home-page仕様にて、モックデータが空の場合のメッセージ表示とローディング表示のシナリオを含んでいる
- routing仕様にて、存在しないパスへの404ハンドリングとルーター設定の集約を定義している
- 各仕様のシナリオはWHEN/THEN形式で記述されており、テスト可能性が高い

**提案**：
- 現状で十分。MSWのネットワークエラーシナリオ（タイムアウト等）は後続の変更で対応可能。

## 2. ロールバック方案

**ステータス**：⚠️ 警告

**発見事項**：
- 新規プロジェクトの初期コミットであるため、ロールバック自体は不要（初期状態に戻す = `git reset --hard`）
- MSWのService Workerファイル（public/mockServiceWorker.js）は自動生成されるため、ロールバック時は再生成が必要

**提案**：
- MSWのService Workerファイルは `npx msw init public/` で再生成可能であるため、ロールバック時の復旧手順としては十分

## 3. テストカバレッジ

**ステータス**：⚠️ 警告

**発見事項**：
- project-scaffold仕様の「開発サーバー起動」「TypeScriptコンパイル成功」は手動確認シナリオであり、自動テスト化が困難
- msw-api-mock仕様のハンドラテストはVitest + MSW（setupServer）で自動テスト可能
- home-page仕様の表示シナリオはVitest + React Testing Libraryで自動テスト可能。非同期データ取得のテストにはasync utilitiesが必要
- routing仕様のシナリオはVitest + React Testing Library + MemoryRouterで自動テスト可能

**提案**：
- MSWの `setupServer` を用いたハンドラのユニットテストをtasks.mdに含めること
- HomePageの非同期データ取得テストには `@testing-library/react` の `waitFor` / `findByText` を使用すること
- routingのテスト（ルートパスでHomePage表示、未知パスで404表示）を明示的にタスク化すること

## 4. 後方互換性

**ステータス**：✅ 合格

**発見事項**：
- 新規プロジェクトであるため、後方互換性の懸念は存在しない
- MSWは開発環境でのみ有効化され、本番ビルドには含まれないため、本番環境への影響はない

**提案**：
- 該当なし。今後の変更で後方互換性を考慮する必要がある場合、その時点で対応する。

## 全体評価

**分割方向の提案**：
- **グループ1: プロジェクト基盤** - Vite初期化、TypeScript設定、Tailwind CSS統合、スケーラブルなディレクトリ構造作成、ESLint + Prettier設定
- **グループ2: ドメイン層** - InsuranceProduct型定義（modules/products/）
- **グループ3: APIモック基盤** - MSWインストール、ブラウザワーカー設定、ハンドラ定義、データ取得関数
- **グループ4: ルーティング** - React Router設定（router/に集約）、HomePage/404ページ作成（app/views/）
- **グループ5: UI実装** - HomePage商品一覧描画（非同期データ取得含む）、商品カードスタイリング
- **グループ6: OpenSpec連携** - config.yaml、レビューテンプレートの配置
- **グループ7: 検証** - 全テスト実行、ビルド確認
- **グループ8: Git** - 初期コミット・プッシュ

**優先順位付け**：
1. プロジェクト基盤（全ての前提）
2. ドメイン層（型定義はモックとUIの前提）
3. APIモック基盤（UIのデータ取得の前提）
4. ルーティング（ページ表示の前提）
5. UI実装（ドメイン層・モック基盤・ルーティングに依存）
6. OpenSpec連携（他の機能に依存しないため任意のタイミングで可）
7. 検証（全実装完了後）
8. Git（全て完了後）

**粒度の基準**：
- 各タスクは単一の関心に絞る（例：型定義とモックハンドラ作成は別タスク）
- 1タスクあたり1〜3ファイルの変更に収める
- テストは実装と対応させるが、TDDに従いテスト先行でタスクを配置する
- MSW関連のセットアップ（インストール・初期化）とハンドラ定義は別タスクにする
