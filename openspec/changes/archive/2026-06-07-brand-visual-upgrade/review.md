# 品質レビュー

## 1. 境界条件

**ステータス**: ⚠️ 警告

**発見事項**:
- `brand-tokens`: null値・未定義カラートークンのシナリオあり（Tailwindデフォルト動作に委ねる）
- `icon-system`: 未定義アイコン名のシナリオあり（プレースホルダー表示）、空値サイズのデフォルトフォールバックあり
- `header-navigation`: 境界外ステップ番号（0, 7）のクランプシナリオあり
- `home-page-redesign`: 空データ・ローディング中のシナリオあり
- `interaction-animations`: 境界条件のシナリオが不足（アニメーション中の再ホバー、連続クリック時の挙動）
- `brand-footer`: 境界条件のシナリオが最小限（フッター自体が静的コンポーネントのため問題なし）

**提案**:
- `interaction-animations`に「ローディングオーバーレイ表示中に再度APIリクエストが発生した場合」のシナリオを追加検討（実装時に対応）
- チェックボックスのトランジション中に再度クリックされた場合のデバウンス要件は実装時に考慮

## 2. ロールバック方案

**ステータス**: ✅ 合格

**発見事項**:
- design.mdに明確な移行方案とロールバック戦略（git revertで一括取り消し）が記載されている
- 外部APIやデータモデルの変更がないため、ロールバックリスクは低い
- 依存関係の追加（lucide-react）のみであり、`npm uninstall`で容易に削除可能

**提案**:
- 追加パッケージのロールバック手順は不要（git revertでpackage.jsonも戻る）

## 3. テストカバレッジ

**ステータス**: ✅ 合格

**発見事項**:
- 各specにWHEN/THEN形式のテスト可能なシナリオが定義されている
- コンポーネントの表示状態、インタラクション、エッジケースのシナリオが網羅されている
- TDDサイクルに従うことがコンテキストで規定されている

**提案**:
- ビジュアルリグレッションテスト（Storybook等）は今回はスコープ外とする
- アニメーションのトランジション時間のテストは実装時に行う（CSS値の検証）

## 4. 後方互換性

**ステータス**: ⚠️ 警告

**発見事項**:
- HomePage.tsxが大幅な再設計となるため、既存のコンポーネントインターフェースが変更される
- 既存のCSSクラス（bg-gray-50等）がブランドクラスに置換される
- APIレスポンスのデータ構造（Product型）は変更なし
- ルーティング構造（`/` → HomePage）は変更なし

**提案**:
- HomePageの既存テストは新デザインに合わせて更新が必要（tasksで明示的に扱う）
- Product型のインターフェースは維持する

## 全体評価

**分割方向の提案**:

タスクは以下の3つのフェーズにグループ化する:

1. **基盤フェーズ**: デザイントークン定義 → アイコンシステム導入 → UIプリミティブコンポーネント（Button, Card, Badge, Icon）
2. **レイアウトフェーズ**: Header → StepNavigation → Footer → レイアウトラッパー
3. **ページフェーズ**: HomePage再設計（ProductCard, QASidebar, 同意セクション, ボタンエリア） → インタラクション追加 → スクロールトップボタン

各フェーズ内は依存関係に従って順次実行する。

**優先順位付け**:

1. brand-tokens（全コンポーネントの基盤）
2. icon-system（UIコンポーネントで使用）
3. UIプリミティブコンポーネント（Button, Card, Badge, Icon）
4. header-navigation, brand-footer（レイアウト構造）
5. home-page-redesign（メイン機能）
6. interaction-animations（最後に追加する品質向上）

**粒度の基準**:

各タスクは以下のいずれかに相当する粒度とする:
- 1つのコンポーネントの作成（テスト含む）
- 1つの設定ファイルの変更
- 1つのユーティリティ/マッピングの定義
- 1つのページセクションの実装

1タスクあたり2〜5分で完了できる単位とする。大きなコンポーネント（HomePage等）はセクション単位に分割する。
