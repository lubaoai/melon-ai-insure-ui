# 品質レビュー

## 1. 境界条件

**ステータス**：⚠️ 警告

**発見事項**：
- 保険料880円のspecsに0円・15,000円のシナリオは記載されているが、負の値や極端に大きい値のシナリオがない
- 契約希望日の1週間後計算で、月末・年末を跨ぐ場合（例：12月27日→1月3日）の動作が明示的にテストされていない
- ストアの初期値に契約者と同じ住所を住居の所在地に設定するが、契約者住所が空値の場合の動作が記載されていない

**提案**：
- 契約希望日計算ユーティリティのテストで月末・年末跨ぎをカバーする
- 保険料の負値・極端値はUI入力ではなくストア値の表示のみであり、現状の0円・通常値・大額の3シナリオで十分
- 契約者住所が空値の場合の住居の所在地初期値は、空値がそのままコピーされるため問題なし

## 2. ロールバック方案

**ステータス**：✅ 合格

**発見事項**：
- この変更はストアの初期値とコンポーネントのprops追加のみであり、データベース移行やAPI変更を伴わない
- ロールバックはストアの初期値を空に戻し、コンポーネントのpropsを削除すれば完了する
- 既存のデータ構造に破壊的変更はない

**提案**：
- 特になし

## 3. テストカバレッジ

**ステータス**：✅ 合格

**発見事項**：
- 各セクションコンポーネントの初期値表示に対するテストシナリオがspecに定義されている
- ストアの初期値に対するテストが暗黙的に必要（insurancePremium、contractorInfoのデフォルト値等）
- 契約希望日計算ユーティリティのテストが必要

**提案**：
- getDefaultContractDate ユーティリティのテストタスクを含めること
- ストアの初期値テストを更新すること

## 4. 後方互換性

**ステータス**：⚠️ 警告

**発見事項**：
- セクションコンポーネントに新規props（value/defaultValue）を追加するため、コンポーネントのインターフェースが変更される
- 既存のテストでコンポーネントをpropsなしでレンダリングしている場合、新規propsが必須になるとテストが壊れる可能性がある
- ContractCourseSectionの保険料表示がハードコード「0円」からprops/stores参照に変わる

**提案**：
- 新規propsはオプショナルにし、指定がない場合は空値で初期化する後方互換を維持する
- 既存テストを新規propsに対応させるタスクを含める

## 全体評価

**分割方向の提案**：
1. **インフラ層**: getDefaultContractDate ユーティリティ + insurancePremium ストア追加
2. **セクションコンポーネント層**: 各セクションに初期値props追加 + ストア初期値変更
3. **ページ層**: PaymentPage・ApplicationCompletionPage の amount をストア参照に変更
4. **統合確認**: 全テストパス確認

**優先順位付け**：
1. ストア初期値変更 + insurancePremium 追加（基盤）
2. getDefaultContractDate ユーティリティ（契約希望日計算）
3. セクションコンポーネントの初期値対応（ContractDateSection → ContractCourseSection → HousingOverviewSection → ContractorInfoSection → ResidenceLocationSection の順）
4. ページ層の保険料表示修正
5. 全テスト統合確認

**粒度の基準**：
- 各タスクは1つの関心に絞る（例：1コンポーネント = 1タスク、1ユーティリティ = 1タスク）
- TDDサイクルごとに1コミット
- ストア変更とコンポーネント変更は分離する
